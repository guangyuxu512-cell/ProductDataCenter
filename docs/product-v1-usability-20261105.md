# 商品库第一版可用性修复与发布记录

日期：2026-11-05。范围是现有 ProductDataCenter 的最小修复，不重做页面或架构。本文件记录实现、验收和正式发布状态；实际运行版本必须以 NAS 容器镜像标签和镜像 ID 核验，不能用代码合并、CI 或镜像生成代替。

## 已实现

- 单条、批量、保存后自动预检统一提交到采集项目 0009 迁移提供的 `product_prechecks` 队列，并复用 API 进程内现有 Runner；没有新增表、迁移或独立 Worker。
- 手动重排会增加 revision、清除旧结果并使旧 claim 失效。前端也按 revision 和更新时间合并状态，连续保存时旧响应不能覆盖新结果。
- 编辑草稿即时更新可直接判断的标题、主图、SKU、类目和属性问题；保存成功立即显示排队中，保存失败和预检请求失败分开提示。问题带页签、字段和 SKU 定位信息。
- 抖音按数据包中当前已保存类目检查；拼多多和无确定类目的手动商品用完整标题及主图推荐，用户确认后才保存。已确认类目不自动重选。类目/属性规则继续使用持久缓存和原手动刷新入口。
- 属性控件按真实平台字段 `type`、`multiple`、`allow_create`、`options` 区分单选、多选、文本、数字和自定义值。允许的自定义值可以添加、保存、读回；禁止自定义的输入不会保存或通过预检。人工值优先，来源包只做可靠对应。
- 批量结果弹窗已移除。每行状态放在商品 ID 复制图标后；批量期间可翻页，工具栏只显示完成数/总数。
- 图片操作区限制在各自卡片内并允许换行。主图使用原生拖放调整草稿顺序，保存后写入数据包和 `product_images.sort_order`；详情图仍保留原排序能力。
- 图片预览作为顶层弹层处理 ESC：第一次只关预览，商品编辑弹窗和未保存草稿保留；第二次恢复原有弹窗关闭/放弃确认。
- 原商品、共享 PostgreSQL、图片上传、SKU 编辑、导出、RPA 数据包读取、多店自动分配和中控 Session 机制未改。

### 尚待现场复核

精确图片 URL 使用 Tailscale 私网地址。当前验收 Windows 未安装或加入该 Tailnet，同机 Docker bridge 也不是独立 Tailnet 客户端，因此无法把对 `100.91.242.119:3612` 的超时当成真实异地 RPA 成功或失败。发布已确认 Tailscale Serve 配置成功、局域网图片路由成功，但仍需在**已加入同一 Tailnet 的实际 RPA 机器**上对上方精确 URL 做一次 HTTP 200 下载复核；在此之前不把“异地 Tailnet 图片访问”标记为通过。

发布及迁移的一次性 DSM 任务已全部禁用，避免定时重复执行。旧镜像、Compose 备份、数据库备份和数据卷均保留。

本次实际采用的发布顺序：

1. 确认共享 PostgreSQL 已由采集项目正式迁移入口安装 0009，商品库角色具备队列表所需权限；ProductDataCenter 不运行 DDL。
2. 使用 GitHub CI 对精确提交生成带完整 SHA 标签的 API/Web 镜像包并核对 SHA-256。
3. 复用现有正式库备份，在隔离恢复库对候选镜像验证商品、队列、保存、图片和 RPA；不删除数据库、卷或商品。
4. 保留现有 Compose、数据库连接、RPA 配置、中控店铺 Session、图片持久目录和旧镜像，仅把 API/Web 镜像切到同一个候选 SHA。
5. 正式核对容器实际镜像、已有商品读取、实际上传并保存一张图片、RPA 数据包读取及匿名图片路由；精确 Tailscale URL 留给已加入同一 Tailnet 的实际 RPA 机器现场复核。任一已执行的关键项失败即恢复旧 API/Web 镜像，不回滚或删除数据库数据。
