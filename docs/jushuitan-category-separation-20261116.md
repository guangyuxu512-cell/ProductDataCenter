# 聚水潭来源类目与抖店类目

聚水潭采集程序在创建商品时将采到的类目 ID 和中文名写入 `edit.category`：旧版本可能传聚水潭类目，新版本可能传已经通过商品库树核实的抖店类目。商品库仅在同一家店的持久类目缓存中核对到完整路径、名称和叶子节点时，将入库类目同时用作抖店目标；未核实时保留来源并进入推荐流程。读取商品不会自动改库；对已在旧版保存抖店类目的特定商品，可在确认采集来源和已选目标后，以版本校验的独立修复补充来源及目标元数据，保留商品包原有字段及属性。

新采集商品同时记录 `_productDataCenterJushuitanSource.category`，避免后续修改目标类目时丢失来源。商品库在编辑已有聚水潭商品时，使用既有 `douyinTarget.category` 和 `douyinTarget.attributes` 存储用户确认的抖店类目与属性。未确认抖店类目时，Worker 使用完整标题和主图请求候选，等待用户确认；已确认时只对该目标类目读取属性表。编辑弹窗分别显示来源和抖店目标。RPA 带 `category_names=required` 时只有确认并可解析目标类目后才返回目标路径，原包和普通导出不变。

资料编码使用 `sourceProductId` 字符串，支持中文和同平台精确去重。聚水潭 RPA 投影只在读取副本中加入稳定商品身份、抖店目标类目和目标属性，数据库原包保持不变；RPA 客户端需要支持 `jushuitan`，并且在目标类目不可用时拒绝退回来源类目上架。客户端代码、运行软件和真实上架验收应分别确认。

此前版本错误地把来源类目作为抖店类目发起预检；现有失败记录不会因代码更新自动变成通过，需重新预检。该修正不代表 Worker、平台类目推荐或实际 RPA 客户端均已通过真实环境验收。
