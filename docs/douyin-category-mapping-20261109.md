# 抖音商品类目中文映射

抖音商品以 PostgreSQL 中当前 UU 的 `goodsInfo.catId1` 至 `catId4` 为准，`0` 表示无该级。映射只按完整有序 ID 查询抖店类目树，同一条路径的各级必须来自同一店铺的树；不根据商品标题猜类目，也不修改商品包或人工保存的类目。

类目树优先使用既有持久缓存。缺失分支或缓存中找不到目标 ID 时，复用已授权店铺的现有类目查询与限流，获取真实树节点并缓存；同一分支并发请求合并。成功查询后仍不存在的节点短暂抑制重复请求，手动更新类目会使该状态失效。平台、店铺状态或缓存不可用时不构造中文名称。

列表和编辑窗口自动显示已解析的中文路径；解析期间和无法解析时分别显示“类目解析中”和“类目待确认”，不改变商品编辑草稿。拼多多来源沿用其原有路径与目标类目逻辑。

RPA 可在 `GET /rpa/v1/products/{product_id}/uu` 上传入 `category_names=required`：对抖音商品附加 `_productDataCenterCategory`，其中 `levels` 是有序的 `{id, name}`，`path` 是对应中文路径。`goodsInfo.catId1`～`catId4` 不变，SHA-256 计算覆盖实际返回的完整字节；无法确认完整路径时返回 `RPA_CATEGORY_UNAVAILABLE`，不能把数字作为名称。未传此参数的原接口和历史快照保持兼容；拼多多 UU 不被改写。使用该能力需要更新 RPA 客户端，客户端仍以 ID 核对平台类目。

当前代码需完成仓库检查、恢复备份的隔离验证及实际部署核验后才能记为生产上线。真实 RPA 上架应单独验证，不以模拟解析或镜像生成替代。
