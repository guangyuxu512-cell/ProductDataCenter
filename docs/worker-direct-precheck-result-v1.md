# Worker 预检直接回传

商品库提交预检时请求 `delivery: product`，随后等待 Worker 直接 POST `/api/v1/worker-precheck-results/{task_id}`，不再向中控轮询结果。Worker 使用已有设备身份；商品库临时使用该身份向中控核验任务、设备和授权，中控不接收结果正文。请求必须通过 HTTPS，设备凭据不写入日志、结果或 URL；原 RPA 只读 Token 的权限不变。

接收端使用现有预检队列按商品及 revision 防止旧结果覆盖，保存内部回执以识别重复提交；内部回执不对商品页面输出。相同结果重发返回成功，不同结果冲突拒绝，过期 revision 返回过期回执。收到平台属性后继续执行原有商品检查，失败仍显示安全原因。

不新增数据库表或 Migration。中控先支持该协议，商品库再部署，Worker 升级至 0.5.1 并完成设备授权后才启用 Worker 预检。关闭 Worker 预检可回到原有预检流程；待发送的结果保留在 Worker outbox，不直接删除。

隔离 HTTPS 和 PostgreSQL 联通验证覆盖了直接回传、商品库入库与中控仅记录摘要；平台响应使用合成替身，真实店铺预检仍需单独验收。

Worker 0.5.4 若收到平台明确要求重新登录，商品库沿用同一商品和 revision 的现有队列等待中控换一家授权店铺；没有可用店铺时继续等待 RPA 更新会话。网络、无权限及风控错误不按会话失效处理。中控尚不支持此规则时保留原失败行为。商品库通过 `X-Precheck-Protocol: 2` 协商状态，已替换任务的相同结果重发只返回回执，不覆盖当前结果。先发布兼容中控，再发布商品库和新版 Worker；不增加 Migration。
