# 拼多多来源类目查询 V1（开发候选）

此能力只把拼多多来源类目 ID 解析为拼多多类目路径，不推断抖店目标类目，不改变商品、草稿或原始采集包，也不声称平台预检完成。

用户提供的 `pdd_categories.csv` 本次只用于本地验证，不随仓库提交。该文件有 17,682 条类目，其中末级 15,225 条；文件 SHA-256 为 `e1fc7e78ca4e20873aa6912b6426a537d237020f242cbfd9b09dda1305601b21`。这只是所验证文件的指纹，不是对未来平台最新状态的保证。

`BACKEND_PDD_CATEGORY_CSV` 配置用户类目表在后端容器或本地进程中的绝对路径，`BACKEND_PDD_CATEGORY_SHA256` 配置经确认的完整文件 SHA-256；运行时应只读挂载包含 CSV 的目录。两项默认均未设置。文件缺失、读取失败、层级不自洽、校验值不匹配或版本切换中的异常返回 503，不使用旧数据冒充新表。层级检查无法独立证明文件是否完整，须由使用者确认文件并配置其 SHA-256；更新字典时需同步更新确认过的校验值，并按发布流程重建服务以加载新的环境配置。不要假设单文件 bind mount 在宿主机原子替换后会自动指向新 inode；目录挂载和新 SHA 需在 NAS 隔离容器验证。应用不会修改文件或数据库，响应携带实际读取内容的 SHA-256。

`GET /api/v1/source-categories/pinduoduo/{category_id}` 沿用管理端鉴权，且只有单独启用 `BACKEND_ENABLE_SOURCE_CATEGORY_READS` 后可用，不要求启用商品编辑写入；携带 RPA 只读凭据不能访问。如果管理与 RPA 凭据误设为相同值，本接口拒绝访问并返回 503。现有 LAN 网页模式会为受信局域网内未携带凭据的访问注入管理凭据，沿用该模式的访问边界；它不是人员登录。成功返回来源平台、来源 ID、逐级 ID/名称及隐藏/删除标记、末级标记和字典指纹。未知或格式无效的 ID 返回 404；类目隐藏、删除标记只是原表事实，不能代替平台可发布性检查。现有 RPA 接口和凭据不变。

应用对该接口的成功和错误响应都设置 `Cache-Control: no-store`，防止更新字典后继续复用旧的“未找到”；代理在请求到达应用之前产生的错误不属于这一保证。

`deploy/compose.pdd-source-categories.yaml` 是可选叠加配置，可用于基础 Compose 或 Synology LAN 配置，使用 `PDD_CATEGORY_DIRECTORY` 只读挂载目录、`PDD_CATEGORY_SHA256` 指定经确认的校验值；开关默认仍关闭。是否启用以及 NAS 目录准备都留给独立发布验收，不因本候选而修改现有容器。

本次还没有接入商品草稿读取、抖店类目推荐、属性表单、批量预检或结果回写。此功能依赖尚未合并的商品编辑候选，未合并、未部署；应先完成独立审查和验证，再由正式发布流程安排文件挂载。
