# 商品库服务器迁移准备

日期：2026-11-10。目标是将商品库 API 和当前共享 PostgreSQL 迁至现有服务器；商品库新上传或生成的图片继续保存到 NAS，并沿用可供 RPA 读取的公网图片 URL。原平台图片继续使用原地址。本文记录准备和隔离演练，不代表正式迁移或上线。

## 实际现状

- 正式商品库 API、Web 上次核验的运行镜像为 `22414b60e1b45effc69be0ecf36b1b411a8ff8ab`。仓库 `main` 另含未完成正式验收的类目映射改动，不能直接把最新 `main` 当成当前生产版本。
- NAS PostgreSQL 为 16.15，数据库约 39,525,399 字节。只读核对时有 610 件商品、7,472 条 SKU、15,570 条图片记录、9 个分组和 589 条预检记录。
- 同库还保存 10 台设备、828 条采集任务、900 条采集记录和 681 条接收记录；这些是 NAS 采集系统的数据，不代表中控全部任务位于该库。只读核对时的 828 条任务包括已完成、失败和取消等历史状态。
- 当前采集接收代码在同一事务内更新接收记录、采集记录、商品、SKU、图片记录以及相应任务状态，并使用锁避免覆盖人工编辑。用户已确认整体迁移该数据库，采集服务继续保留在 NAS，切换为连接同一云端数据库。仅迁商品表需要另行设计和验证可靠同步，不能简单拆库。核对 NAS 当前挂载的采集服务关键源码，统一换行后与本地采集项目一致。
- 当前数据库迁移记录为 0001～0009，扩展包括 `pg_trgm` 和 `pgcrypto`。采集项目负责数据库迁移；商品库不自行建立替代表或接管迁移链。
- 当前数据库可见两个业务登录角色：采集库拥有者和受限的商品库角色；采集库拥有者目前具有超级用户权限。隔离恢复没有恢复角色或授权，正式方案需单独建立并验证所需权限，不能把演练用的超级用户当成正式应用账号。设备鉴权依赖库内凭据哈希，完整迁移后仍须实际验证设备连接。
- NAS 商品库自有图片目录中只读核对到 18 个文件，约 13.9 MB。15,570 条图片记录中 1,137 条有本地路径；当前没有“仅有本地路径、没有来源 URL”的记录，但迁移仍应保留本地回退能力。
- 类目/属性缓存位于独立持久 SQLite 卷，不能当成 PostgreSQL 的一部分遗漏。店铺授权仍由现有中控负责；不复制或更改 Session。
- 目标服务器现场核对约 2 核、3.6 GiB 内存、根盘约 37 GiB 可用，已有中控、签名器和 PostgreSQL 15 服务；现场曾有约 544 MiB swap 占用。正式容量和并发仍需测量，不能覆盖或复用中控已有数据库。
- 服务器通过现有私网链路成功下载 NAS 自有图片，HTTP 200、`image/png`、68 字节；现有公网图片地址从工作站读取也为 HTTP 200。反方向在服务器 Tailnet 地址临时监听无数据测试端口，NAS 主机访问超时；NAS 对该地址的系统路由走普通局域网网关，未走 Tailnet 接口。该结果不单独证明防火墙或 ACL 原因。NAS 采集容器到服务器 PostgreSQL 的受限连接尚未建立或验收。
- NAS 主机访问服务器现有公网 HTTPS 健康接口返回 200；服务器至 NAS 的 Tailnet SSH TCP 端口可达，尚未进行 SSH 登录或建立隧道。NAS 为 DSM 7.3.2，主机没有 `tailscale0` 接口和 `/dev/net/tun` 字符设备。Tailscale 官方说明 [DSM 7 默认不为其他 NAS 应用启用出站 Tailnet 连接](https://tailscale.com/docs/integrations/synology#enable-outbound-connections)，与本次路由现象相符，但尚未排除其他网络限制。其出站配置方案需要调整主机设置并重启 Tailscale，可能影响现有 RPA 与图片链路；准备阶段未执行。
- 进一步通过 NAS 的 `tailscale nc` 对服务器 Tailnet 地址上的临时无数据测试端口建立连接并取得预期响应，表明两节点之间的 Tailscale 守护进程链路可用。普通 NAS 程序和采集 Docker 容器仍不能据此直接连接云数据库；还需验证正式的路由或受控转发方案及断线恢复。
- 追加真实 PostgreSQL 16 网络演练：服务器在仅 Tailnet 地址上启动独立空测试库，使用合成凭据；NAS 主机经临时本机 TCP 转发和 `tailscale nc` 同时建立 3 个连接，执行临时表事务并得到预期结果，错误密码被拒绝。停止测试库后连接失败，重启测试库并重建临时转发后再次成功；测试库已停止。这只证明主机级短时演练，不代表采集 Docker 容器的持续连接、正在执行事务的恢复或生产转发服务已经验收。
- 在 NAS 的采集容器所属 Docker 网络中，启动独立测试转发容器，并用当前正在运行的采集容器镜像启动隔离客户端。该客户端使用真实 `pg` 驱动，通过 NAS 的 Tailscale 守护进程连接服务器空测试库：5 个并发临时表事务成功，错误密码被拒绝；测试库停止后连接失败，重启后使用新客户端的 5 个并发事务再次通过。测试转发器和服务器测试库均已停止，未切换正式采集服务。这是短时隔离演练，未验证已有连接在故障时的事务结果，也未建立或部署长期转发服务；临时转发器曾挂载 Tailscale 控制 socket，正式方案须评估其权限范围。
- 服务器至 NAS 的 Tailnet SMB TCP 端口探测可达；没有执行共享目录挂载或凭据验证，不能据此认定历史本地图片回退已经可用。
- 商品库桌面客户端默认指向原 NAS 地址，当前 RPA 客户端代码固定使用原 Tailnet 商品库地址。正式切换必须同时规划客户端更新或旧地址兼容转发，不能只修改服务器端。
- 商品库前端和中控都使用根路径下的 `/api/v1`，现有公网 443 默认入口已由中控使用；直接把该路径改指商品库会影响中控。应使用独立域名或端口，或者完整适配独立路径及相应客户端，再验证 TLS、鉴权和中控原有路由。
- 服务器现有 HTTPS 证书包含服务器公网 IP。一次只返回固定测试文字的临时 `8444` 端口探针从当前工作站公网访问超时；探针已停止。服务器 UFW 处于启用状态，但此次结果不能单独确定拦截发生在哪一层，正式入口仍需落实并做外网验证。

## 2026-11-10 隔离演练

- 校验并使用 2026-11-09 22:28 的既有备份，在服务器独立 PostgreSQL 16 容器中恢复。隔离容器使用 `network none`，没有公网或私网数据库监听；不连接正式采集服务。还原时使用 `--no-owner --no-acl`，因此不代表正式账号、所有权和授权已经验证。
- 恢复后核对到 610 件商品、7,472 条 SKU、15,570 条图片记录、9 个分组、589 条预检记录、10 台设备、828 条任务、900 条采集记录、681 条接收记录，以及 0001～0009 迁移记录和所需扩展。
- 使用已部署的 `22414b6` 镜像启动同网络隔离的商品库 API，关闭外部中控和抖店连接。商品列表、详情、分组、预检状态查询、RPA 分组和分组商品读取通过；抽取 5 件商品核对 RPA UU 摘要，并核对一件商品的 RPA 数据包与导出内容一致。管理凭据和 RPA 凭据分离检查通过。
- 首次脚本因对 HTTP 响应头大小写的处理错误产生断言失败；修正核验脚本后，以上检查重新通过。隔离环境未测试真实抖店类目接口、真实新采集、NAS 图片写入或外部 RPA 下载。
- 昨晚备份与本次只读核对的当前商品包摘要不同，不能作为正式切换数据。切换前须在暂停写入并排空任务后重新备份，并核对新备份与目标库。
- 检查本次既有演练备份的归档清单，未发现 ACL 项；即使正式恢复使用该备份也不能依赖它恢复账号授权。切换前应独立导出并校验所需角色、权限和数据库对象归属，且继续使用全新备份。
- 只读核对了现有商品库数据库角色的表级和字段级权限。随后在服务器隔离 PostgreSQL 中用非超级用户作为数据库拥有者重新恢复备份，并给另一个测试角色配置与现有商品库角色一致的权限；验证了禁止建表、禁止修改未授权字段，同时允许商品、SKU、图片和分组的既有操作，以及商品保存触发预检记录。测试事务已回滚。
- 使用上述受限测试角色运行隔离 API，读取原有 610 件商品，并新建、编辑、分组、导出一件测试商品，RPA 分组和 UU 读取通过；测试结束只清理该次新建的测试商品和分组，商品总数仍为 610。隔离 API 与数据库已停止。该测试使用无外部网络的隔离库和测试身份；正式库仍须配置实际登录凭据及权限，不能照搬演练库的本地信任认证。
- 演练 API 和数据库容器均已停止，隔离备份和数据库数据保留；没有切换或删除正式数据库、数据卷或商品。演练期间正式商品库和中控健康接口保持可读。
- 图片上传候选准备分支代码提交 `b10ae0736fb574a07db6e32e4db957ccebab0031` 及文档更新提交 `03f4dac` 通过 GitHub 的后端、前端、容器和 Windows 桌面 CI；本地另用独立空 PostgreSQL 执行集成测试 25 项通过。该分支基于当前生产镜像对应代码，不代表已合并最新 `main` 或已部署。

## 迁移实施方案和门禁

1. 将云端独立 PostgreSQL 16 作为唯一正式数据源，保留现有数据库迁移归属。先在隔离环境验证角色、权限、扩展、触发器、设备凭据哈希、任务、商品包和预检队列；NAS 采集服务通过受控私网连接云库。不得将数据库端口直接发布到公网。
2. 服务器部署商品库 API/Web，先保持线上现有版本行为；类目映射和平台 `10008` 问题独立验证，不随迁移冒充已修复。迁移持久缓存，并安全配置既有中控连接，不输出凭据。
3. 沿用 NAS 自有图片目录和既有图片公网 URL。云端上传入口必须通过受保护的私网图片写入路径调用 NAS，保留格式/大小校验和原子写入；对外图片读取保持现有只读路径。不要把 NAS 局域网代理自动注入管理凭据的行为直接暴露到公网。基于当前生产镜像的图片写入候选已在独立工作树实现，并通过服务器至 NAS 实际图片服务的隔离写入测试；正式图片服务尚未部署或验收。
4. 确认并保留历史本地图片回退路径，验证原平台 URL 不被改写；新上传/生成的主图、详情图、规格图保存和顺序在页面、导出与 RPA 中一致。
5. 确认与中控不冲突的云端地址、TLS 和独立授权方式，准备桌面客户端与 RPA 的更新或过渡转发。验证现有 RPA 凭据仍仅能访问只读接口。
6. 切换前停止接收新采集与商品写入，排空进行中的工作后制作新备份，恢复云库并校验数据、角色、迁移、设备身份与接收记录，再按可回退步骤切换采集服务和商品库。NAS 保留原库、原卷和图片。
7. 一旦云库开始接收新写入，回滚前必须先暂停写入并将新数据安全带回或完成反向恢复；不能直接指回旧 NAS 库而丢失切换后的修改。
8. 上线后分别验证真实采集入库、编辑保存及自动预检、主图/详情图/规格图上传和读回、导出、RPA 包和公网图片下载；报告实际运行版本与未完成的真实场景。
