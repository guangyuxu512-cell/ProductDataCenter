# 抖店类目选择与缓存

选择器使用平台 `categoryOptionsN`，从根类目开始按父类目逐层读取，保存每层的 ID、名称及是否末级。逐级列表搜索只过滤已加载的结果；用户还可以从当前层搜索平台类目。平台搜索结果必须与当前已选的完整上级路径一致，并且成功读取该结果的属性表后才能确认；保存使用平台返回的类目 ID 和已读取的上级 ID，不根据商品标题猜测类目。搜索接口不返回完整的末级标记，不能据此宣称平台所有类目都已覆盖。

类目树按查询上下文与父类目缓存，属性定义按查询上下文与类目缓存。商品库自动使用已授权的查询上下文，不要求用户选择店铺。缓存未命中、用户主动搜索或手动更新时才请求抖店，平时仍向中控确认当前已授权上下文；不会将 Cookie、签名、商品标题或商品属性值写入缓存。

属性缓存不会按时间自动过期。正式预检取得实时属性表后，会与同一店铺、同一类目的缓存比较；规则确有变化时使该类目的旧缓存失效，下次打开时重新读取，纯选项顺序变化不会触发失效。不会改写已保存的商品属性，也不会为此反复预检。手动更新类目或属性仍可主动获取平台数据，更新失败保留旧缓存。尚未重新预检或手动更新的缓存不能保证实时反映平台变化；平台尚未明确返回的规则仍不会自行推断。

类目缓存保存在独立的持久 SQLite 文件，不修改手机采集 PostgreSQL 表、不存储商品包。部署须保持 `BACKEND_CATEGORY_CACHE_FILE` 的持久挂载并备份缓存文件；缓存不可用时类目查询显示错误，不伪装成已缓存。生产发布仍需执行项目约定的备份、隔离验证和真实只读联调。

在商品编辑弹窗确认类目只会修改编辑草稿；用户点击保存后写入商品数据包。搜索的补充结果不代表逐级列表已经完整，也不自动改写现有商品的类目。
