# 抖店类目选择与缓存

选择器使用平台 `categoryOptionsN`，从根类目开始按父类目逐层读取，保存每层的 ID、名称及是否末级；只允许选择平台返回为可选的末级类目。后续手动创建商品可复用同一选择器。平台返回的目录仍可能受当前店铺和平台状态影响，不能把单店的返回当作已验证的平台全部权限。

类目树按店铺与父类目缓存，属性定义按店铺与类目缓存。只有缓存未命中、手动更新或首次访问新店铺时才请求抖店，平时仍向中控确认当前已授权店铺；不会将 Cookie、签名、商品标题或商品属性值写入缓存。缓存不会自动过期。手动更新类目成功后，旧类目树缓存失效，未展开分支在下次展开时重新读取；更新失败保留旧缓存。手动更新属性仅更新所选类目，失败保留旧值。平台规则、店铺状态或类目发生变化时应手动更新，静态缓存不能保证覆盖所有动态必填条件。

缓存是 NAS 上独立的持久 SQLite 卷 `product-category-cache`，不修改手机采集 PostgreSQL 表、不存储商品包。Compose 的类目查询覆盖配置挂载该卷并设置 `BACKEND_CATEGORY_CACHE_FILE`；API 镜像预设目录归属 `1026:100`。发布时核实卷写入与重建后保留，备份该卷；迁移时保持同一卷或明确备份恢复。缓存不可用时类目查询显示错误，不伪装成已缓存。生产发布仍需执行项目约定的备份、隔离验证和真实只读联调。

当前商品弹窗选择类目后只用于查看对应表单，**尚未保存到商品或数据包**；商品编辑、手动创建及数据包版本同步仍需单独接入。既有 RPA 路由和商品源文件不变。
