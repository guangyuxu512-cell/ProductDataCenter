## 尚未完成

- 搜索是逐级列表缺项时的补查方式，不代表已经取得平台完整类目树，也不保证自动推荐一定有结果；历史商品不会自动改类目。正式接口对 `Z-719` 商品以其已有标题和主图重新查询推荐，仍返回零个候选；尚未拿到平台原始推荐响应，不能断言是平台没有推荐还是传输投影遗漏。
- Worker 返回的属性仍只包含投影后的部分平台数据，非空 `unit_rules` 等规则不完整；“水洗标/吊牌图”的页面节点已经定位，原始接口响应和写入方式尚未确认，商品库暂不能上传、保存或据此声称预检完整。已交中控/Worker 负责人核对。
- 部分自定义材质的旧文本无法唯一拆分名称和数字时会保留原文，预检不会将不确定的规则当作通过；例如未能用真实选项消除歧义的 `自定义99%`。尚未验证这类值的分项回填，也未宣称所有服装三级类目均已适配。

## 对照实际抖店页面

- 在用户打开的 HuanYu 发布页只读核对 `服装 → 内衣裤袜 → 袜子 → 连体袜`，类目 ID `1000010274`；页面显示的“面料材质”属性 ID 为 `785`。水洗标/吊牌图入口旁写有“上传图片可智能识别并预填材质信息”，本例没有显示必填星号；面料下拉展示棉、聚酯纤维等选项，并提示材质含量总和需要 100%。未上传图片、保存或发布商品。
- 同一授权店铺下主动刷新该类目的属性，商品库收到 20 项，其中面料材质的顶层选项为零，也没有图片入口字段。抖店已加载的页面代码显示，该复合材质组件从 `additions.measure_templates` 的 `value_modules[0].value_options` 构造选项；图片组件读取 `category_property_pic` 中与属性 ID 对应的节点，图片值使用 `urls`。
- 页面实际运行模型中，模板 `873` 的枚举模块 `1854` 有 250 个材质选项；数值模块 `1855` 的单位为 `%`、范围 `0.01–100`、精度为 2。`category_property_pic` 下的属性 `785` 节点当前可见且非必填。这是页面运行模型，不等同于已取得原始 HTTP 响应；回归样例只保留其中四个选项，不含商品填写值。
- Worker 当前只投影 `category_properties.items`，其度量模块白名单不包含 `value_options`；生产商品库的归一化也尚未解析该嵌套选项。这能解释为什么刷新后可选材质仍可能缺失。商品库侧解析修正正在准备，但需要 Worker 先传递真实选项并进行联调；图片节点没有进入当前商品库契约，不能仅加一个上传按钮冒充完整支持。
- 抖店组件会分别检查数值、重复材质和填写完整性，并对 `category_property_material` 发起服务端校验；商品库目前没有校验材质比例合计。尚未抓取此页面的原始 `getSchema` 响应、识图调用和最终发布请求，因此图片字段是否来自该响应、识别如何触发以及发布时的完整保存格式仍待核验；不能把页面代码推断成已验证的接口返回或 RPA 发布行为。
