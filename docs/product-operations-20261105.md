# 商品删除、尺寸和多选属性

本轮在现有商品编辑、PostgreSQL、预检队列和类目缓存上实现单删、批删及属性修复；不增加数据库表、Worker、回收站或商品复制功能。

## 功能与数据边界

- 单个和批量删除都通过同一受商品写入开关和管理身份保护的接口完成。删除 `products` 行及其数据库商品包，由采集项目现有 `ON DELETE CASCADE` 外键清理 SKU、图片和预检记录；不删除任何图片文件。导出和 RPA 仍以数据库为准。采集系统仍可在后续采集时重新入库相同商品。
- 商品库角色需要由数据库管理员定向授予 `DELETE ON public.products`；不新增迁移或改变其他表的权限。授权前先备份，并在隔离恢复库使用同等权限角色验证外键级联。
- 尺寸控件由平台 `measure_templates.value_modules` 的输入段、前后缀、单位、必填、范围和精度驱动；平台标记为普通文本的尺寸仍是文本。无法识别的原值显示并保留，未经用户保存不会改写。
- 多选使用平台 `max_input_num`、选项 ID 和 `diy_type`；没有预设选项但明确允许自定义的多选也支持添加。旧编码只在全部片段唯一匹配该字段的选项时拆分，保存后写回商品包。
- 当前类目表单规则缓存升级为版本 3，旧版首次读取重新取得平台规则，成功后继续持久缓存；属性值不写入缓存。不显示自行添加的“平台规则待核对”等字段说明；不能完成规则校验时预检不能显示通过。

## 平台响应样例与待验证项

- 已实际读取类目 `1000005146`（居家日用 / 收纳整理工具 / 收纳架）和 `1000001535`（玩具 / 益智早教玩具 / 智力思维训练）的 `getSchema`。前者“尺寸”为文本，“包装尺寸”为三段带单位的 `measure`；后者“规格尺寸”为三段数值加 `cm`、`m` 或 `mm` 单位，“适用年龄”为最多 5 项的多选。
- 脱敏字段样例位于 `backend/tests/fixtures/douyin-schema-1000005146.json` 和 `backend/tests/fixtures/douyin-schema-1000001535.json`，仅保留表单规则和选项，不含店铺 Session 或商品包。
- 本文提交时生产部署和隔离验证结果尚未确认，应以实际发布核验记录为准；不能将代码提交或 CI 通过写成上线。

## 发布顺序

1. 固定候选提交，完成项目 CI、PG16 集成测试与浏览器回归，并按现有流程生成 API/Web 镜像。
2. 备份现有 PostgreSQL，恢复到隔离库，验证定向授权、单删、批删、关联记录清理、共享图片保留及上述属性的保存、导出和 RPA 读回。
3. 由已有数据库管理员流程只向商品库实际角色授予 `public.products` 的 `DELETE`，保留现有数据库、采集记录、图片目录、RPA 配置和中控店铺 Session；商品库自身不执行 DDL。
4. 按现有流程切换 API/Web 镜像，核对运行版本与健康状态；仅使用专门创建的测试商品核验单删、批删及两类真实类目属性，不删除用户现有商品。
